API reference

Polytopes and warmup

PolytopeSamplers.Polytope — Type
Polytope(lower, upper; A, b, C, d)

The convex polytope of points x with lower .<= x .<= upper, A * x .<= b and C * x .== d. Bounds may be infinite as long as the constraints bound the polytope. A coordinate with lower[i] == upper[i] is fixed at that value.

A, b, C and d default to no constraints. Constraints of the form L * x .>= f are A = -L, b = -f.

isempty(P) solves a linear program to check whether P has any points, and x in P checks a point (see isfeasible).

Examples

julia> P = Polytope([0.0, 0.0], [1.0, 1.0]; A = [1.0 1.0], b = [1.0])  # a triangle
Polytope in 2 variables with 1 inequalities and 0 equalities

julia> [0.2, 0.3] in P
true

julia> isempty(P)
false

PolytopeSamplers.warmup — Function
warmup([rng], P::Polytope; extremes = false, rounding = :ellipsoid,
       optimizer = HiGHS.Optimizer, atol = 1e-6)

Prepare P for sampling and return a Warmup to sample from.

With extremes = false (the default), solve one linear program for the largest ball inside P in the slice of C * x .== d and the fixed coordinates, as in multiphase Monte Carlo sampling (mmcs). A polytope with room for a ball of positive radius has no other equalities. If the ball has radius below atol, P has equalities beyond the explicit ones, and warmup falls back to extremes = true.

With extremes = true, solve 2n linear programs, minimizing and maximizing each of the n coordinates. The extreme points locate the constraints that hold with equality over all of P: a coordinate whose range is within atol of zero, or an inequality whose slack is within atol of zero at every extreme point. Chains move only in the directions that keep these equalities and C * x .== d. The 2n programs cost far more for large n: 58 s for n = 200 with 1000 constraints, against 1.3 s for the whole warmup with extremes = false. ACHR uses the extreme points, and solves the 2n programs on first use when the warmup was built without them.

rounding changes coordinates so that the polytope is close to round, which makes every sampler take long steps in thin directions:

  • :ellipsoid (or true): map the maximum-volume inscribed ellipsoid to the unit ball, repeatedly, until it is nearly a ball. Each round factors dense matrices of size the number of constraints.
  • :samples: draw billiard-walk samples and map their principal axes to equal lengths, repeatedly, as in multiphase Monte Carlo sampling. Uses rng.
  • :none (or false).

Throws an ArgumentError when P is empty or unbounded; with extremes = false one more linear program checks boundedness. optimizer is any JuMP optimizer for linear programs; each call builds its own model, so separate tasks may call warmup at the same time.

PolytopeSamplers.Warmup — Type
Warmup

A polytope in the coordinates that samplers move in, built by warmup. Points are x = center + transform * z for z in {z : G z ≤ h}, where z has one coordinate per direction in which the polytope has width and the rows of G have unit norm.

  • polytope: the Polytope sampled.
  • points: the distinct extreme points of each coordinate, one per column.
  • center: the point z = 0, the center of the last inscribed ellipsoid when rounded, otherwise the center of the largest inscribed ball, or the mean of points with extremes = true.
  • transform: the n × k matrix taking z to x - center. Its columns are orthonormal when not rounded.
  • G, h: the constraints of P in z, leaving out those that are constant on the slice.
  • zpoints: points in z coordinates.
  • radius: the radius of the largest ball in {z : G z ≤ h}, near 1 when rounded.
  • rounded: whether transform rounds the polytope.

With warmup(P; extremes = false) (the default), points and zpoints have no columns; ACHR computes the extreme points when a chain first needs them.

Targets

PolytopeSamplers.Target — Type
Target(w::Warmup, ℓ; gradient = nothing)
Target(P::Polytope, ℓ; gradient = nothing, kwargs...)

The distribution on a polytope with density proportional to exp(ℓ(x)), a model for sample and sample_until_converged. Given a Polytope, the other keyword arguments go to warmup.

ℓ is a function of the vector x of the polytope's variables, or an object implementing the LogDensityProblems.jl interface (logdensity, dimension, capabilities, and logdensity_and_gradient for gradients). For a function, pass gradient = (g, x) -> ..., which fills g with ∇ℓ(x), to use CRHMC. ℓ is called from every chain, on separate threads when Julia has them.

HitAndRun and CoordinateHitAndRun draw each point on the chord from the density along it by slice sampling, so they leave the target invariant for any ℓ (GaussianTarget and ExponentialTarget are drawn exactly on chords); DikinWalk and VaidyaWalk add ℓ to their Metropolis ratio; CRHMC adds -ℓ to its potential and needs the gradient. BilliardWalk and ACHR sample only the uniform distribution.

Examples

P = Polytope(zeros(3), ones(3); C = ones(1, 3), d = [1.0])  # the simplex
# Dirichlet(2, 3, 4) on the simplex
target = Target(P, x -> sum((a - 1) * log(xi) for (a, xi) in zip((2, 3, 4), x));
                gradient = (g, x) -> (g .= ((2, 3, 4) .- 1) ./ x))
r = sample_until_converged(Xoshiro(1), target, CRHMC())
source
PolytopeSamplers.GaussianTarget — Function
GaussianTarget(w::Warmup, μ, Σ)
GaussianTarget(P::Polytope, μ, Σ; kwargs...)

The Gaussian distribution with mean μ and covariance Σ (a positive definite matrix) restricted to the polytope: a Target with ℓ(x) = -(x - μ)ᵀ Σ⁻¹ (x - μ) / 2. Given a Polytope, the other keyword arguments go to warmup.

On a chord the density is a truncated normal, which HitAndRun and CoordinateHitAndRun draw exactly, without slice sampling. The other samplers that take densities use ℓ and its gradient as for any target.

Examples

box = Polytope(fill(-1.0, 2), fill(1.0, 2))
t = GaussianTarget(box, [0.5, 0.0], [1.0 0.8; 0.8 1.0])
r = sample_until_converged(Xoshiro(1), t, CoordinateHitAndRun())
source
PolytopeSamplers.ExponentialTarget — Function
ExponentialTarget(w::Warmup, c)
ExponentialTarget(P::Polytope, c; kwargs...)

The distribution with density proportional to exp(-cᵀx) on the polytope: a Target with ℓ(x) = -cᵀx. Given a Polytope, the other keyword arguments go to warmup.

On a chord the density is a truncated exponential, which HitAndRun and CoordinateHitAndRun draw exactly, without slice sampling.

Examples

P = Polytope(zeros(3), ones(3); C = ones(1, 3), d = [1.0])  # the simplex
r = sample_until_converged(Xoshiro(1), ExponentialTarget(P, [1.0, 5.0, 20.0]), HitAndRun())

Sampling

StatsBase.sample — Method
sample([rng], w::Warmup, method, n; discard_initial = 0, thinning = 1, progress = true)
sample([rng], w::Warmup, method, MCMCThreads(), n, nchains; kwargs...)
sample([rng], t::Target, method, args...; kwargs...)
sample([rng], P::Polytope, method, args...; extremes = false, rounding = :ellipsoid,
       optimizer = HiGHS.Optimizer, kwargs...)

Draw n points from the uniform distribution on a polytope, or from the density of a Target, returned as the columns of a matrix; with MCMCThreads(), MCMCSerial() or MCMCDistributed(), draw nchains chains and return a vector of matrices. method is CoordinateHitAndRun, BilliardWalk, HitAndRun or ACHR.

Every chain starts at a uniform random point of the largest ball inside the polytope, so the chains of an ensemble start apart, as R̂ in diagnostics assumes; pass initial_params, a point of the polytope (a vector of points, one per chain, with an ensemble), to choose the start. The chain then discards discard_initial steps and keeps every thinning-th point. Consecutive points are correlated; check the effective sample size with diagnostics. Given a Polytope, sample calls warmup once for all chains with the given extremes and rounding. To run chains until they converge, see sample_until_converged.

With MCMCChains.jl loaded, chain_type = Chains returns an MCMCChains.Chains (one for all chains of an ensemble), with parameters named x[1], x[2], … or by param_names, and the statistics of each step (AbstractMCMC.getstats, such as is_accept or n_reflections) in its internals section. AbstractMCMC.steps and callbacks receive each point as a transition with fields x and stats.

This is AbstractMCMC.sample (also StatsBase.sample); its other keyword arguments, such as initial_state and callback, apply.

Examples

P = Polytope([0.0, 0.0], [1.0, 1.0]; A = [1.0 1.0], b = [1.0])  # a triangle
X = sample(Xoshiro(1), P, HitAndRun(), 1000; discard_initial = 100, thinning = 10)
chains = sample(Xoshiro(1), P, ACHR(), MCMCThreads(), 1000, 4; progress = false)
diagnostics(chains)
X = sample(Xoshiro(1), P, HitAndRun(), 1000; initial_params = [0.1, 0.1])

PolytopeSamplers.sample_until_converged — Function
sample_until_converged([rng], w::Warmup, method = BilliardWalk(); target_ess = 1000,
                       max_rhat = 1.01, nchains = 4, n = 1000, max_n = 1_000_000,
                       thinning = 1)
sample_until_converged([rng], t::Target, method = HitAndRun(); kwargs...)

Run nchains chains, on the uniform distribution of a Warmup or the density of a Target, and double their length until the second half of the chains has a smallest effective sample size of at least target_ess and a largest R̂ below max_rhat over the varying coordinates; the first half is discarded as burn-in (Gelman & Rubin 1992). The first round keeps n points per chain; rounds stop once max_n points per chain are kept.

Each chain starts at a random point of the largest ball inside the polytope and has its own random number generator, seeded from rng, so the result does not depend on the number of threads; chains run on separate threads when Julia has them.

Returns a named tuple: chains (one matrix per chain, a point per column), diagnostics (see diagnostics), n (points kept per chain) and converged. A warning is logged when the chains have not converged by max_n.

source
PolytopeSamplers.mmcs — Function
mmcs([rng], P::Polytope; target_ess = 1000, optimizer = HiGHS.Optimizer, kwargs...)

Multiphase Monte Carlo sampling (Chalkis et al. 2021): prepare P with one linear program and rounding from billiard-walk samples (warmup(rng, P; extremes = false, rounding = :samples)), then run billiard-walk chains until they reach target_ess with R̂ below 1.01 (sample_until_converged, which takes the other keyword arguments).

Returns the named tuple of sample_until_converged with the warmup added.

This differs from the volesti implementation in its stopping rule: volesti sums the ESS of single chains across phases, including the rounding phases, and restarts each window of 100 points near the center; here the rounding samples are discarded and several chains run until R̂ also shows they agree.

Chalkis, A., Fisikopoulos, V., Tsigaridas, E. & Zafeiropoulos, H. (2021). Geometric algorithms for sampling the flux space of metabolic networks. 37th International Symposium on Computational Geometry (SoCG 2021), 21:1–21:16. https://doi.org/10.4230/LIPIcs.SoCG.2021.21

source
PolytopeSamplers.diagnostics — Function
diagnostics(chains; kind = :bulk)

Effective sample size and split-R̂ of every coordinate, from one chain (a matrix with one point per column) or several chains of equal length (a vector of such matrices), as returned by sample.

Returns a named tuple:

  • ess, rhat: one value per coordinate, NaN for coordinates that are constant over every chain, such as fixed coordinates.
  • mean, std: the mean and standard deviation of each coordinate over all chains.
  • mcse_mean, mcse_std: their Monte Carlo standard errors, which account for the correlation between points; report estimates with these as error bars.
  • min_ess, max_rhat: the smallest ESS and the largest R̂ over the varying coordinates.

kind = :bulk measures the center of each marginal and kind = :tail its 5% and 95% quantiles (Vehtari et al. 2021). A common rule is to run until max_rhat < 1.01 and min_ess is at least 100 per chain. Computed with MCMCDiagnosticTools.jl.

Vehtari, A., Gelman, A., Simpson, D., Carpenter, B. & Bürkner, P.-C. (2021). Rank-normalization, folding, and localization: an improved R̂ for assessing convergence of MCMC. Bayesian Analysis 16, 667–718. https://doi.org/10.1214/20-BA1221

Samplers

PolytopeSamplers.BilliardWalk — Type
BilliardWalk(; trajectory_length = nothing, max_reflections = nothing)

The billiard walk (Gryazina & Polyak 2014) in its accelerated form (Chalkis et al. 2021): each step draws a direction uniformly from the sphere and a length from the exponential distribution with mean trajectory_length, and moves that far, reflecting off the facets of the polytope. The chain is reversible with the uniform distribution as its stationary distribution, and crosses a rounded polytope in a few steps, as a trajectory is not stopped by the first facet it meets.

trajectory_length defaults to 2√k r in the coordinates of the warmup, for dimension k and inscribed radius r (Warmup.radius, near 1 after rounding), as in volesti. A trajectory that makes more than max_reflections reflections (default 1000k) is abandoned and the chain stays put for that step. A reflection costs O(m) for m constraints, as the rates G v are updated from the precomputed G Gᵀ, an m × m matrix that the chains on one Warmup share.

Gryazina, E. & Polyak, B. (2014). Random sampling: billiard walk algorithm. European Journal of Operational Research 238, 497–504. https://doi.org/10.1016/j.ejor.2014.03.041

Chalkis, A., Fisikopoulos, V., Tsigaridas, E. & Zafeiropoulos, H. (2021). Geometric algorithms for sampling the flux space of metabolic networks. 37th International Symposium on Computational Geometry (SoCG 2021), 21:1–21:16. https://doi.org/10.4230/LIPIcs.SoCG.2021.21

source
PolytopeSamplers.CoordinateHitAndRun — Type
CoordinateHitAndRun(; moves = nothing, scan = :cyclic)

Coordinate hit-and-run: each move resamples one coordinate of the warmup uniformly on its chord. On a rounded warmup this is CHRR (Haraldsdóttir et al. 2017), the default sampler of the COBRA Toolbox. For a Target, each move draws from the density along the chord by slice sampling.

With scan = :cyclic (the default, as in hopsy) the coordinates are taken in turn; with scan = :random each is chosen at random and the chain is reversible. Both keep the target stationary; the cyclic scan gave 1.3 to 1.8 times the effective samples per move on the polytopes of the test suite.

A move costs O(m) for m constraints, as the slacks are updated in place, and each step of the chain makes moves moves (default: the dimension k of the warmup), so a step costs about as much as one of HitAndRun. Moves per effective sample grow as k².

A chain started exactly at a vertex never moves when no coordinate axis points into the polytope there, as on a simplex; sample and sample_until_converged start chains inside the largest inscribed ball, away from vertices, unless given initial_params.

Haraldsdóttir, H. S., Cousins, B., Thiele, I., Fleming, R. M. T. & Vempala, S. (2017). CHRR: coordinate hit-and-run with rounding for uniform sampling of constraint-based models. Bioinformatics 33, 1741–1743. https://doi.org/10.1093/bioinformatics/btx052

source
PolytopeSamplers.HitAndRun — Type
HitAndRun()

Hit-and-run (Smith 1984): each step draws a direction uniformly from the unit sphere in the coordinates of the warmup and moves to a uniform point on the chord of the polytope along it. The chain is reversible, with the uniform distribution as its stationary distribution. A step costs O(mk) for m constraints in k dimensions. For a Target, the point on the chord is drawn from the density along it by slice sampling.

Smith, R. L. (1984). Efficient Monte Carlo procedures for generating points uniformly distributed over bounded regions. Operations Research 32, 1296–1308. https://doi.org/10.1287/opre.32.6.1296

source
PolytopeSamplers.CRHMC — Type
CRHMC(; initial_step_size = 0.2, effective_step_size = 1.0, max_ode_steps = 30,
      implicit_tol = 1e-5)

Constrained Riemannian Hamiltonian Monte Carlo (Kook, Lee, Shen & Vempala 2022): Hamiltonian dynamics in the metric of the log barrier, which slows the chain down only in the directions in which a facet is near, so it takes long steps through the whole polytope.

CRHMC writes the polytope as {x : A x = b, l ≤ x ≤ u} with a diagonal barrier metric projected onto A x = b, which keeps large sparse problems cheap. Here the dynamics run in the coordinates z of the Warmup: with slacks s = h - G z as the bounded variables, the projected metric is g(z) = Gᵀ S⁻² G, the Hessian of the log barrier of G z ≤ h, and the Hamiltonian is

H(z, p) = ½ log det g(z) + ½ pᵀ g(z)⁻¹ p,

minus the log density for a Target.

Each step refreshes the momentum partially (p ← √μ p + √(1 - μ) g^½ ξ with μ = 1 - h / effective_step_size), takes one step of the Strang splitting of the potential and kinetic parts, solving the kinetic part by the implicit midpoint rule with fixed-point iterations (up to max_ode_steps, to a local-norm tolerance implicit_tol), and accepts by a Metropolis filter on H; a rejection reverses the momentum. The step size h grows from 0.001 to initial_step_size over the first 10 effective steps, then shrinks by a factor of 1.1 whenever rejections, failed integrations or integration effort exceed their targets, as in the reference implementation. A step factors the k × k metric once or twice, O(mk² + k³) each, and each implicit iteration costs O(mk).

The metric is affine-invariant, so in exact arithmetic the chain behaves the same in any coordinates, but its condition number grows as the square of the polytope's aspect ratio, and badly scaled polytopes need the default rounding: on a rotated box with sides from 1e-3 to 1e3 without rounding, chains reached points 1e-6 from a facet where every integration failed, and stayed there.

A step whose implicit integration does not converge is rejected. As failures happen more often near the boundary, they bias the chain slightly toward the interior; the metric is refactored during slow integrations to keep them below about 0.1% of steps, where the bias was not detectable over 20 seeds.

Kook, Y., Lee, Y. T., Shen, R. & Vempala, S. S. (2022). Sampling with Riemannian Hamiltonian Monte Carlo in a constrained space. Advances in Neural Information Processing Systems 35. https://arxiv.org/abs/2202.01908

source
PolytopeSamplers.DikinWalk — Type
DikinWalk(; r = 0.5)

The Dikin walk (Kannan & Narayanan 2012): each step proposes a Gaussian move shaped by the Dikin ellipsoid of the log barrier at the current point, N(z, (r²/k) H(z)⁻¹) with H(z) = Gᵀ S⁻² G for slacks S, and accepts it by a Metropolis filter, so the chain has the uniform distribution as its stationary distribution, or the density of a Target, whose log density joins the Metropolis ratio. The walk is affine-invariant, so it needs no rounding, and it has a mixing bound of O(mk) steps from a warm start for m constraints in k dimensions, whatever the shape of the polytope. A step costs O(mk²). On rounded polytopes it needed 340 to 490 steps per effective sample, about 100 times the BilliardWalk; use it as an independent check, or when rounding is not available.

Kannan, R. & Narayanan, H. (2012). Random walks on polytopes and an affine interior point method for linear programming. Mathematics of Operations Research 37, 1–20. https://doi.org/10.1287/moor.1110.0519

source
PolytopeSamplers.VaidyaWalk — Type
VaidyaWalk(; r = 0.7)

The Vaidya walk (Chen, Dwivedi, Wainwright & Yu 2018): the DikinWalk with each constraint weighted by its leverage score plus k/m (Vaidya's volumetric barrier), and proposals N(z, (r²/√(km)) H(z)⁻¹). Its moves per effective sample grow as O(m^½ k^1.5) instead of O(mk), which helps when there are many more constraints than dimensions; a step costs about twice a Dikin step.

Chen, Y., Dwivedi, R., Wainwright, M. J. & Yu, B. (2018). Fast MCMC sampling algorithms on polytopes. Journal of Machine Learning Research 19, 1–86. https://jmlr.org/papers/v19/18-158.html

source
PolytopeSamplers.ACHR — Type
ACHR()

Artificial centering hit-and-run (Kaufman & Smith 1998), as in the COBRA Toolbox: each direction runs from the running mean of the chain to a random extreme point of a coordinate, so directions follow the shape of the polytope. The direction depends on the history through the mean, so the chain is only approximately Markov, and its distribution approaches uniform as the mean settles; on rounded polytopes it is the slowest method here. It samples only the uniform distribution.

A warmup built with extremes = false (the default) solves the 2n linear programs for the extreme points when the first ACHR chain starts, and its chains share them.

Kaufman, D. E. & Smith, R. L. (1998). Direction choice for accelerated convergence in hit-and-run sampling. Operations Research 46, 84–95. https://doi.org/10.1287/opre.46.1.84

source
PolytopeSamplers.PolytopeSampler — Type
PolytopeSampler

Supertype of the samplers: BilliardWalk, the hit-and-run methods (AbstractHitAndRun), DikinWalk, VaidyaWalk and CRHMC. All of them move in the coordinates of a Warmup, rounded by default. A sampler S implements chain_state(S, model) for a Warmup (and, if it samples densities, a Target), returning a state with fields warmup, z and x (the current point), and step!(rng, state).
